Topic Builder

From Interest to Claim

관심사를 논증 가능한 주제로 바꾸는 기본 문장입니다.

  • My topic focuses on ...
  • This issue matters because ...
  • I argue that ...
  • This argument is supported by ...
Paragraph Frame

Evidence Paragraph

한 문단이 하나의 기능을 갖도록 구성합니다.

  • This paragraph argues that ...
  • For example, ...
  • This evidence suggests that ...
  • Therefore, this point supports ...
Source Integration

Citation and Explanation

자료를 가져온 뒤 반드시 자신의 해석을 붙입니다.

  • According to ...,
  • This finding is important because ...
  • However, this source does not fully explain ...
  • In my paper, this source helps show ...
AI Use Note

Responsible AI Statement

AI를 사용한 경우 사용 범위와 검증 과정을 투명하게 기록합니다.

  • I used AI tools to brainstorm possible outlines.
  • I revised all AI-generated suggestions myself.
  • I checked facts, citations, and final wording independently.
  • AI was not used to replace my own analysis.

Revision Clinic

수정 체크리스트

Clarity

Is the claim visible?

독자가 첫 문단에서 글의 방향과 주장을 확인할 수 있어야 합니다.

Flow

Does each paragraph have one job?

한 문단에는 하나의 중심 기능을 부여하고, 문단 간 연결을 명확히 합니다.

Integrity

Are sources and AI use transparent?

자료, 인용, AI 사용 범위를 명확히 표시해 학술적 신뢰를 확보합니다.

COURSE CONTEXT → REVIEW → ACTION → RECORD

수업 맥락에서 시작하는 작업 공간

주차와 자료를 확인하고, 할 일을 정한 뒤 변경안을 검토하고 기록합니다.

이 공간은 로그인 없는 개인 작업 도구입니다. 기록은 현재 브라우저에만 저장되며 공식 출석·성적·과제 제출에 반영되지 않습니다. AI 자동 실행, 웹 DB, Drive·Notion·Padlet 연동은 연결되어 있지 않습니다. 학생 이름·성적 등 개인정보는 입력하지 마세요.

구조와 10단계 작업 순서 보기

교수: 지시·판단·최종 확인 / 과목 맥락: 게시된 주차·자료 / 개인 기억: 이 브라우저의 운영기록 / 실행: 변경안 미리보기·저장·내보내기. 출결 예외와 성적 판단은 교수자가 공식 LMS에서 처리합니다.

  1. 과목·주차 선택
  2. 과목 맥락 읽기
  3. 브리핑 확인
  4. 작업 지시 입력
  5. 조회 / 기록 변경
  6. 최신 자료 대조
  7. 변경안 미리보기
  8. 확인 / 수정
  9. 저장 후 대조
  10. 내보내기·기록

조회는 저장 없이 보고합니다. 기록 변경은 최신 게시 자료 대조 → 변경안 → 확인 → 저장 후 재확인 순서입니다. 여기의 확인 체크는 교수 인증이나 공식 승인을 대신하지 않습니다.
